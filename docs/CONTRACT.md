# The contract between Adam's code and Reed's code

This file is the only coupling between the two halves. Agree once, never rename a field. Adding fields is fine; unknown fields are ignored.

## Base URL

Every client reads it from one env var:

```
PODIUM_SERVER_URL=https://xxxx.trycloudflare.com   # Reed's tunnel; http://localhost:3000 for local stubs
```

## Time

Every event carries `ts`, wall-clock ISO 8601 with milliseconds, from the sender's clock. The server converts to `t` = seconds since `session_start`. Senders never compute `t`. Clocks on two laptops and two phones are close enough for a 15-second cue loop.

## POST /events

Body: `{ "type": string, "ts": string, "payload": object }`. Response: `200 {"ok": true}`. Any 4xx/5xx is logged by the sender and ignored; senders never crash on a failed post.

### Event types

**`session_start`** (presenter page or Adam's audio script)
```json
{"outline": [{"title": "Why this matters", "minutes": 2}, {"title": "Demo", "minutes": 4}, {"title": "Ask", "minutes": 1}],
 "planned_minutes": 7}
```

**`transcript_chunk`** (Adam, every ~10 s)
```json
{"text": "so um the thing about pricing is",
 "words": [{"w": "so", "start": 80.1, "end": 80.3, "filler": false},
           {"w": "um", "start": 80.4, "end": 80.7, "filler": true}],
 "chunk_start": 80.0, "chunk_end": 90.0,
 "metrics": {"wpm_60s": 162, "fillers_per_min": 4.0, "seconds_since_pause": 22.5}}
```
`words[].start/end` are seconds since the audio stream began (Adam's clock). `metrics` is computed by the sender over its own rolling window so the cue loop can read it directly. If `metrics` is missing, the server computes from `words`.

**`audience_frame`** (Reed's iPhone page, every 30 s)
```json
{"image_b64": "<jpeg base64, ~640px wide>", "width": 640, "height": 480, "source": "iphone-rear"}
```
Server scores it and appends an `audience_score` event; the raw frame is discarded after scoring and never written to disk.

**`audience_score`** (server-generated)
```json
{"engagement": 3, "heads_up_pct": 60, "phones_out_pct": 25, "hands_raised": 0, "someone_speaking": false,
 "note": "Most people looking up; two on laptops in the back row."}
```

**`slide_change`** (optional, P2)
```json
{"slide_title": "Pricing", "topic": "pricing tiers", "outline_section": "Pricing", "confidence": 0.8}
```

**`cue`** (server-generated by the cue loop, every 15 s or not at all)
```json
{"category": "pace", "text": "Slow down. 168 wpm.", "reason": "wpm_60s 168 > 160"}
```

**`session_end`**
```json
{}
```

## GET /state

What the presenter page polls (every 2 s) or receives over SSE.

```json
{"session": {"started_at": "2026-09-12T21:02:00.000Z", "planned_minutes": 7, "elapsed_s": 143, "remaining_s": 277,
             "current_section": "Demo", "section_over_by_s": 0},
 "cue": {"text": "Slow down. 168 wpm.", "category": "pace", "at": "2026-09-12T21:04:20.000Z"},
 "engagement": {"latest": 3, "series": [{"t": 30, "score": 4}, {"t": 60, "score": 3}]},
 "metrics": {"wpm_60s": 168, "fillers_per_min": 3.0, "seconds_since_pause": 12.0}}
```

`cue` is null when there is nothing to say. The page shows the last cue for 15 s, then blank.

## GET /events?since=<iso>

Returns the full event log (minus `image_b64`) as a JSON array. The recap page calls this once at `/end`.

## Degradation rules

- No `audience_score` events → `engagement.latest` is null, cue loop skips the audience category, recap omits the engagement section.
- No `transcript_chunk` for 30 s → metrics go null, cue loop only fires time-based cues, countdown keeps running.
- Cue phrasing call fails → use the `fallback_text` from `config/cues.json` for that category. The phone never shows an error.
